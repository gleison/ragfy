# Ragfy architecture

The Go daemon assembled in `cmd/ragfy` is the active runtime. Application code lives under `internal`: `service` owns the use cases and HTTP API, `knowledge` defines the persistence contract, `storage/sqlite` implements that contract, `model` defines independent generation and embedding capabilities, `extraction` coordinates and routes generative extraction, `chunking` splits documents, `retrieval` owns similarity and ranking, `digest` validates extracted knowledge, `hook` integrates Codex and Claude, and `platform` handles operating-system concerns. Hook processes are intentionally short-lived and send JSON with an explicit provider source to a token-protected loopback API.

Digest generation uses the CLI for the provider that created the session: `codex exec` for Codex and `claude -p` for Claude. Both implement the same `model.Generator` contract and run without tools, hooks, writes, or session persistence. Extraction accepts only complete JSON with all four arrays, rejects schema placeholders and transient runtime observations, and requires every record to cite exact transcript evidence. A preference or decision can be explicit in a user message or implicitly accepted when an assistant claim is followed by a later user action that clearly relies on it; both quotes are retained. Each extracted record is classified with global or project visibility based on the knowledge itself, not merely the session origin. The service supplies the complete conversational spine, excluding tools, reasoning and injected runtime context. A spine that exceeds the provider-safe limit is split only at message boundaries with overlapping messages; the window candidates are then consolidated and validated against the complete spine. Each category can retain up to four strong records. Inspect extracted content when validating changes, not just document counts or worker completion logs.

The local model selection is fixed in the Go app: `Qwen/Qwen3-Embedding-0.6B-GGUF/Qwen3-Embedding-0.6B-Q8_0.gguf` provides multilingual embeddings, using `last` pooling and an English retrieval instruction on queries.

The app downloads the missing embedding GGUF into its application data directory and checks its pinned SHA-256 value before loading. It tracks the embedding model version in the repository and re-embeds stored documents when that version changes. Provider selection happens only in `cmd/ragfy`; the service depends on the `extraction.Extractor` interface. `knowledge.Repository` is the persistence boundary; `storage/sqlite.Repository` is the first implementation and is also selected only in composition. Generation, embedding, extraction, chunking and retrieval are separate dependencies. A Supabase adapter can implement persistence and a database-native retriever without changing the service package.

`ragfy setup` registers the background service and both `UserPromptSubmit` and `SessionEnd` hooks for Claude Code and Codex. Recall returns global knowledge plus knowledge scoped to the current working-directory project. `ragfy ingest <folder>` indexes Markdown, RST, and text files globally without generative extraction; `ragfy ingest --project <name> <folder>` restricts them to one project.
